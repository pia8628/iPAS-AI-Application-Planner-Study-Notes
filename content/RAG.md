# RAG
中文名稱：檢索增強生成
英文名稱：Retrieval-Augmented Generation
# 定義（Definition）
先從知識庫檢索相關文件，再把結果餵給生成式模型作回答或摘要，結合「找資料」與「寫答案」的流程，能降低幻覺並對特定領域提供可追溯的回應。
# 原理與技術
RAG 的核心管線：
1. **文件切片與向量化**：原始文件分段（長度與重疊需調校），用 **Embedding 模型** 轉向量；可加 **metadata**（來源、日期）。
2. **索引建置**：把向量存入向量資料庫（FAISS、Milvus 等），可搭配 **倒排索引/關鍵詞索引** 做混合檢索。
3. **檢索(Recall/Rank)**：使用 **向量相似度** 找候選，再用 **重排序(Re-ranking)** 提升相關性，避免只靠語意相似卻無重點。
4. **提示組裝(Prompt Construction)**：把問題、檢索段落、格式指示組成提示，可包含 **引用標記** 方便追蹤來源。
5. **生成(Generation)**：LLM 根據提示產生答案；可限制字數、語氣、語言並要求列出引用。
6. **後處理與記錄**：抽取引用、過濾敏感詞、寫入日誌，並評估答案品質。
常見加強：**多路檢索(Multi-vector / multi-query)**、**分層檢索**（先主題後細節）、**查表/規則混合**、**Contextual Compression** 移除冗語。品質關鍵是 **切片粒度、檢索相關性、提示格式**；安全面需做 **來源追蹤、拒答策略、版本控制**。評估可用 **Hit@K、MRR、BLEU/ROUGE、人工審閱**。部署時要考慮 **快取、延遲、資料更新頻率** 與權限控制。
# 應用領域
- **企業知識庫問答**：政策、SOP、產品手冊；可附來源連結，支援審計。
- **法務與合規查詢**：引用法條與條款，降低胡編；需維護版本，避免舊法誤用。
- **客服與售後**：根據 FAQ 與工單給答案，並記錄引用，方便人工複核。
- **醫療與科學摘要**：從論文與指南檢索段落，生成摘要或比較，需加上安全拒答規則。
- **程式碼助理**：從 repo 索引文件與程式碼片段，生成解釋或建議，並標註檔名行號。
- **商業分析**：結合資料庫查詢結果與文件，產生決策報告，需做資料權限與遮罩。
共通重點：資料切片策略、檢索器品質與提示格式決定 RAG 成敗；要持續監控引用正確率、幻覺率與來源覆蓋率，並建立更新/重建索引流程。
# 3 題模擬練習題
1. RAG 與純生成式模型最大差異？
   - A. RAG 不需要模型
   - **B. 先檢索外部資料再生成，答案可追溯**
   - C. RAG 只能處理英文
   - D. RAG 只用規則
   - 正確答案：B；解析：RAG 把檢索結果放入提示，降低幻覺並可附來源。
2. 檢索品質不佳的常見原因？
   - A. 模型太大
   - **B. 切片過大或過小導致向量無法對準問題**
   - C. 沒有 GPU
   - D. 檔名太長
   - 正確答案：B；解析：切片粒度與重疊影響召回，需調整長度與重排序策略。
3. 為何在答案中加入引用標記？
   - A. 讓模型更快
   - **B. 提供可追溯性與人工審核依據**
   - C. 避免向量計算
   - D. 方便截斷資料
   - 正確答案：B；解析：引用能提升信任、支持審計與除錯，也符合合規需求。
